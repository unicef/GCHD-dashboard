# Infrastructure data pipeline
**The entire /scripts folder can be completely ignored for app deployment, runs independently to orchestrate infrastructure data** 

Fetches schools, health facilities and water points from four public sources, normalises them to one schema, and uploads them to Google Earth Engine as table assets.

**Adding a country needs no code change and no redeploy.** The dashboard discovers whatever is in the GEE infrastructure folder at runtime, so a new country appears as soon as its assets are uploaded.

```
fetch_*.py  ──▶  prep_infra.py  ──▶  upload_infra.py  ──▶  the app discovers it
  raw CSVs        one schema          GEE table assets
```

---

## Setup

```bash
pip install geeup                                   # upload tool (no GCS needed)
geeup auth --cred ../app/credentials/service_account.json
cp .env.example .env                                # then fill in your API keys
python sync_adm0.py                                 # refresh the ISO3 -> name table
```

### API keys — `scripts/.env`

| Key | Needed for | How to get one |
|---|---|---|
| `GIGA_SCHOOL_LOCATION_API_KEY` | Giga schools | [maps.giga.global](https://maps.giga.global/) |
| `HEALTHSITES_API_KEY` | healthsites.io | [healthsites.io/enrol](https://healthsites.io/enrol) — sign in with an OpenStreetMap account |
| `WPDX_APP_TOKEN` | *optional* | [WPdx developer settings](https://data.waterpointdata.org/profile/edit/developer_settings) — only raises the rate limit |

mWater and WPdx work with no key at all. A source whose key is missing is **skipped with a warning**, not a failure — a partial key set still produces usable output. `scripts/` is git-ignored, so `.env` will not be committed.

### Earth Engine

`geeup tabup` runs as your **personal** Earth Engine login (it calls bare `ee.Initialize()`), not as the service account registered with `geeup auth`. That call needs a project, so `~/.config/earthengine/credentials` must contain:

```json
{ "project": "unicef-ccri", ... }
```

Without it the upload fails with `Not signed up for Earth Engine or project is not registered`, which reads like a permissions problem but is not.

Assets are created under your account, so the app's service account needs **read access** to them.

## Commands

```bash
# fetch + prep, all available sources
python run_pipeline.py --iso3 mwi --iso3 gha

# one source
python run_pipeline.py --iso3 mwi --source giga

# preview without calling any API
python run_pipeline.py --iso3 mwi --dry-run

# upload — filters compose (--iso3 / --source / --layer)
python upload_infra.py --iso3 mwi --source giga --dry-run
python upload_infra.py --iso3 mwi --source giga
```

`--upload` on `run_pipeline.py` runs the whole chain in one go.

### Large or interrupted runs

`--skip-existing` means the same thing everywhere: **leave what's already there alone**. On the fetchers it skips countries already downloaded; on the upload it skips assets already in GEE. Both make a run safely repeatable.

```bash
python run_pipeline.py  --all-countries --source giga --skip-existing
python upload_infra.py  --all-countries --source giga --skip-existing
```

Use `--overwrite` when you *want* to refresh existing assets. It is mutually exclusive with `--skip-existing`; passing both is an error rather than a silent guess.

A global run produces a long tail of "no records returned" — no source covers all 195 countries. Those are reported and skipped, not failures.

## Scripts

| Script | Role |
|---|---|
| `_common.py` | Shared helpers: `.env` loading, adm0 lookup, HTTP retries, paths, `asset_stem()`. Not a CLI. |
| `sync_adm0.py` | Export the canonical ISO3 → country-name table from the adm0 GEE asset |
| `fetch_mwater.py` | mWater REST API — schools, health facilities, water points |
| `fetch_giga_schools.py` | Giga school locations |
| `fetch_healthsites.py` | healthsites.io health facilities |
| `fetch_wpdx_water.py` | WPdx+ water points |
| `prep_infra.py` | Normalise every source to the output contract |
| `upload_infra.py` | Upload to GEE via geeup, validating asset names first |
| `run_pipeline.py` | Drive fetch → prep → upload for a set of countries |
| `test_pipeline.py` | Tests — offline by default, `--live` adds real-API checks |

Every fetcher takes repeatable `--iso3`, plus `--skip-existing` and `--out-dir`. The paginated ones (Giga, healthsites, WPdx) also take `--max-pages` for smoke tests; mWater returns a whole country per request, so it has none. Run any script with `-h` for its full options.

### Data files

| File | Contents |
|---|---|
| `adm0_countries.json` | 195 ISO3 → country names, generated by `sync_adm0.py` |
| `state_countries.json` | The 195 sovereign-state ucodes that define the pipeline's scope |
| `mwater_countries.json` | mWater's 255 level-0 region ids (cache) |
| `iso3_mwater_review.csv` | ISO3 ↔ mWater name mapping, for review |

## Output

```
app/data/infra/{iso3}/raw/{source}_{layer}.csv          exactly as fetched
app/data/infra/{iso3}/out/{iso3}_{source}_{layer}.csv   normalised, upload-ready
                        /{iso3}_{source}_{layer}.geojson  for local inspection
```

### The contract — identical for every source

| Column | Notes |
|---|---|
| `facility_id` | Stable id from the source; row index as a last resort |
| `name` | `""` when genuinely unknown — never the string `"nan"` |
| `longitude`, `latitude` | Numeric, EPSG:4326; rows without both are dropped |
| *extras* | Only where the source has them: `education_level` (Giga), `subtype`, `status` |

`facility_type`, `source` and `iso3` are deliberately **not** columns — they are implicit in the asset name, so there is one source of truth and no column can contradict the asset it lives in.

### Asset naming — `{iso3}_{source}_{layer}`

This is load-bearing, not a convention: geeup turns each CSV's filename into the GEE asset id, and the app parses that id back into a country and layer. An asset named wrongly uploads cleanly and is then **invisible to the app**, so `upload_infra.py` validates every name before uploading.

| Part | Values |
|---|---|
| `iso3` | lowercase ISO3, from adm0 |
| `source` | `giga`, `healthsites`, `wpdx`, `mwater`, `hdx`, `co` |
| `layer` | `schools`, `health_facilities`, `water_points` |

Assets land in `projects/unicef-ccri/assets/infrastructure`. The app's `discover_infra_assets()` lists that folder (cached, 10-minute TTL) to build the Infrastructure tab's dropdowns.

### Country-office submissions (`co`)

`co` is data sent in by a country office rather than fetched from an API, so it
has no `fetch_*.py` — the files arrive by email and are dropped straight into
`app/data/infra/{iso3}/raw/` as `co_schools.csv`, `co_health.csv`,
`co_water.csv`, then run through `prep_infra.py` like any other source.

`scripts/templates/` holds the blank CSVs to send offices, and
`scripts/templates/README.md` is the guide that goes with them (required
columns, the coordinate rules that catch most bad submissions, and what not to
include). Column matching for these jobs is case-insensitive and accepts the
usual `lon`/`long`/`x` and `lat`/`y` spellings, since offices export from QGIS,
Excel, KoBo and ODK.

## Tests

```bash
python test_pipeline.py          # offline: no network, no credentials
python test_pipeline.py --live   # adds real-API checks
```

The offline tier covers the output contract, the naming rule, `.env` parsing and country resolution, and cross-checks that the app's discovery regex accepts everything the pipeline writes. The live tier verifies the API behaviours the design depends on.

## Notes for whoever maintains this

Things learned the hard way, all currently guarded by tests:

- **mWater ignores `offset`.** Every request returns the same first page, so a limit/offset loop never terminates and silently yields massively duplicated data. Country scoping sends admin-region ids in batches of 2000 instead (measured: ~4000 ids works, ~5000 gives HTTP 400/414).
- **Never fuzzy-match country names.** It mapped Saint-Barthélemy to France and Kosovo to Serbia, and "Congo" is a substring of both Congos. adm0 is the naming authority; per-source alias tables bridge to each API's spelling, and an unknown country is a loud error naming the line to add.
- **Collapse whitespace in text fields.** GEE's CSV parser mis-splits quoted multi-line values, which shifts the lon/lat columns and corrupts geometry. A real case: a school named `"Mpatawamilonde c\nCDSS"`.
- **WPdx's `clean_country_id` is already ISO3** — no ISO3→ISO2 conversion needed.
- **healthsites.io filters by country name only**, and its spellings differ from adm0's formal UN names. A country returning zero features with a valid key usually means a spelling to add to `ISO3_HEALTHSITES_NAMES`.
- **The app must not read these files at runtime.** The pipeline is offline tooling: it writes CSVs on a workstation and uploads them to GEE. The running app only ever queries the resulting assets.

### Adding a source

Add one entry to `JOBS` in `prep_infra.py` (which file, which layer, where to find id/name/coordinates/extras) and, if it needs one, a label in `_SOURCE_LABELS` in `app/gee_core.py`. A test checks every source has a label. No new code path.
